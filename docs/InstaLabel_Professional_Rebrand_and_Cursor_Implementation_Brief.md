# InstaLabel Professional Rebrand and Cursor Implementation Brief

**Prepared:** 20 September 2026  
**Purpose:** A design, content, information architecture and implementation specification that can be given directly to Cursor to rebuild the public InstaLabel marketing website.  
**Scope:** Public marketing site only. Preserve application functionality, authentication, billing and the existing customer dashboard unless a separate product-UI project is approved.

**Revision note:** This version adds explicit visual-preservation rules: existing hero layouts must remain intact, existing relevant imagery and evidence sections must not be removed while final photography is pending, and existing InstaLabel label-renderer outputs must be reused instead of substituted with random label graphics.

## 2. What the current site communicates, and why it weakens trust

The supplied full-page screenshot and live site show that purple is not merely a gradient. It controls the logo, headings, buttons, badges, icon containers, illustration highlights, section backgrounds, mobile-app banner, chat widget and footer. Because nearly every element uses the same saturated family, colour no longer communicates meaning or hierarchy.

The visual issue is reinforced by the content. The current homepage and secondary pages repeatedly use patterns associated with low-trust generated SaaS sites:

- gradient text and glowing purple backgrounds;
- numerous small rounded cards;
- emojis as product icons;
- floating mockups and decorative UI fragments;
- generic phrases such as “transform your kitchen” and “smart labelling”;
- repeated CTA modules on almost every page;
- unsupported numerical precision;
- absolute compliance language;
- duplicated content under many URLs;
- anonymous or weakly attributed testimonials;
- claims that conflict between pages.

Examples currently visible on the live site include “100% Natasha’s Law & EHO Compliant,” “500+ UK restaurants,” “0% error rate,” “95% reduction in labelling time,” “98% first-time pass rate,” and “23% error rate.” These must not survive the redesign unless each has a documented, reviewable source and a defined measurement method.

There are also product-truth conflicts:

- Desktop support is described as “any USB printer” in places, but the stronger and more accurate proposition is any properly installed printer the operating system can print to through PrintBridge.
- Android support is sometimes implied to cover Bluetooth printers generally, while confirmed direct support is model-specific.
- The current site repeatedly names **MUNBYN RW114B**. The confirmed model is **MUNBYN RW411B**.
- The Android page mentions USB and Sunmi support in ways that conflict with the confirmed current roadmap.
- Repeated CTAs say the product works with an “existing Epson printer,” which unnecessarily narrows the desktop proposition.
- “No internet required,” “offline mode,” local caching and automatic reconnection are presented inconsistently. Keep these only after engineering verifies exact behaviour for each platform.

This rebrand must fix the source of these inconsistencies, not merely rewrite visible text.

## 3. The 2025 SaaS benchmark and how to use it correctly

There is no universal award for “the number one SaaS company.” The cleanest recognised 2025 benchmark is the **Forbes Cloud 100**, produced with Bessemer Venture Partners and Salesforce Ventures. Forbes lists **OpenAI at number one for 2025**. Use that as the named primary inspiration, while recognising that OpenAI and InstaLabel serve very different audiences.

Sources:

- [Forbes Cloud 100 2025](https://www.forbes.com/lists/cloud100/)
- [Forbes profile showing OpenAI’s 2025 Cloud 100 rank](https://www.forbes.com/companies/openai/)
- [Cloud 100 methodology](https://www.forbes.com/sites/bessemerventurepartners/2025/09/03/the-cloud-100-methodology-making-the-definitive-list-of-the-worlds-top-private-cloud-companies/)
- [OpenAI website](https://openai.com/)

### Principles to take from OpenAI

- Neutral canvases create confidence and let content carry the brand.
- Large typography is used for a few important messages, not for every section.
- Navigation is restrained and grouped by user intent.
- Product, research, customer stories and company information are separated clearly.
- Colour does not need to saturate every component to make a brand recognisable.
- Real work, real stories and meaningful imagery create authority.

### Supporting design references

OpenAI is the named 2025 benchmark, but InstaLabel should also borrow relevant execution principles from:

- [Stripe](https://stripe.com/gb): a direct value proposition, credible numbers only when measured, product architecture explained clearly and customer proof attached to named outcomes.
- [Linear](https://linear.app/): real product UI shown prominently, disciplined typography, limited navigation and feature sections organised around workflows rather than generic benefits.

Do not imitate any of these sites visually. Translate their discipline into the commercial-kitchen context.

### The benchmark translated into InstaLabel

| Benchmark principle | InstaLabel implementation |
|---|---|
| Neutral environment | Warm white canvas, white surfaces, ink text and steel borders |
| Product shown early | Real video of product selection and a label printing in the hero |
| Specific positioning | “Kitchen labelling without proprietary hardware” |
| Proof before promotion | Supported-printer table, real labels, real dashboard and named pilots |
| Clear information architecture | Product, Labels, Solutions, Resources, Pricing |
| Restraint | One primary CTA, one secondary CTA and no repeated purple promotional strips |

## 4. Brand strategy

### Brand idea

> **The reliable labelling layer for a professional kitchen.**

InstaLabel should feel like something a head chef, kitchen manager or operations director can trust during service. It should not feel like a speculative AI product.

### Brand pillars

1. **Practical**  
   It solves daily labelling work with a short, understandable workflow.

2. **Compatible**  
   Desktop customers can keep properly installed printers. Android support expands through tested model integrations.

3. **Controlled**  
   Managers configure product data and rules centrally. Staff use those approved settings when printing.

4. **Traceable**  
   Print records show what was printed, when and by whom, where the product supports this.

5. **Honest**  
   The brand distinguishes software support from a business’s legal responsibilities and distinguishes current compatibility from planned support.

### Audience priority

| Priority | Audience | Core concern | Message |
|---:|---|---|---|
| 1 | Independent restaurant owner or manager | Remove handwriting without buying a locked hardware system | Keep your printer. Replace the manual process. |
| 2 | Head chef or kitchen manager | Fast, consistent labelling during prep | Choose the item, check the details and print. |
| 3 | Café, bakery or takeaway operator | PPDS ingredients and allergens | Manage product data once and produce consistent PPDS labels. |
| 4 | Multi-site operations manager | Consistency across teams and sites | Control products, users and templates centrally. |
| 5 | Caterer or mobile operator | Portable printing | Use Android with a supported Bluetooth printer. |

### Brand personality

An experienced kitchen operations manager who understands software: calm, direct, prepared and never theatrical.

### What the brand is not

- An AI company looking for a kitchen use case.
- A replacement for food-safety expertise.
- A legal compliance guarantee.
- A proprietary printer company.
- A generic restaurant management suite.
- An enterprise platform before the evidence supports that label.

## 6. Typography, spacing and UI rules

### Typography

- **Primary family:** `Inter`, variable font, self-hosted where licensing and performance allow.
- **Optional display alternative:** `Geist Sans` for headings if already available in the stack.
- **Technical/data text:** `Geist Mono` or `IBM Plex Mono`, only for printer models, status values, dates and code-like identifiers.
- Use sentence case everywhere.
- Do not use gradient text.
- Avoid ultra-bold weights. Use 650–700 for H1 and 600–650 for H2.

Recommended desktop scale:

| Style | Size / line height |
|---|---|
| Display/H1 | `clamp(48px, 5vw, 72px)` / 0.98–1.05 |
| H2 | `clamp(34px, 3.4vw, 50px)` / 1.08 |
| H3 | `24px` / 1.25 |
| Lead | `20px` / 1.55 |
| Body | `16px` / 1.65 |
| Small | `14px` / 1.5 |

Mobile H1 should normally be 40–46px, not a squeezed desktop size.

### Layout

- Maximum site container: `1200px`.
- Long-form reading column: `720px`.
- Desktop section spacing: `96px` to `128px`.
- Mobile section spacing: `64px` to `80px`.
- Use a 12-column desktop grid and simple stacked mobile flow.
- Left-align most marketing copy. Centre alignment is reserved for short section intros and the final CTA.
- Use visible section changes through spacing, imagery and occasional surface colour, not repeated cards.

### Shape and depth

- Button radius: `8px`.
- Card and screenshot radius: `12px`.
- Pills only for true statuses or compact filters.
- Borders: 1px Steel 150.
- Shadows: subtle, low blur and low opacity. No purple shadows.
- Avoid nesting cards inside cards.

### Buttons

- Primary: Ink background, white text.
- Secondary: transparent/white, Ink border and Ink text.
- Text link: Teal with a clear arrow only where useful.
- Destructive and warning buttons use semantic colours, never brand purple.
- Use one primary CTA label globally: **Start free trial**.
- Use one secondary sales CTA: **Book a demo**.

### Icons

- Use one line-icon family such as Lucide.
- Stroke width 1.75–2px.
- No emojis as feature icons.
- Icons illustrate a recognised object or action, not an abstract “AI sparkle.”

### Motion

- Use motion to demonstrate printing or reveal product details, not decorate empty space.
- 150–250ms interface transitions.
- Respect `prefers-reduced-motion`.
- Avoid parallax, floating blobs, looping glow and constant card movement.

## 8. Photography and product imagery

The largest long-term trust improvement will come from genuine product evidence. **For this rebuild, however, do not remove or blank existing image sections while waiting for the final photography. Preserve the current assets and layouts, then progressively replace temporary assets with approved real photography.**

### Existing-asset preservation rule

The current website already contains images and visual assets in many sections. Those assets should be treated as the starting point for the rebuild:

- Keep the existing image in its existing section where it is relevant to the page content.
- Do not swap it for a random stock image, generic SaaS illustration or AI-generated image.
- Do not remove an entire section because its current image is not yet the final real-world photograph.
- Do not change a section's purpose or layout solely because the final photography is still pending.
- When better real photography becomes available, replace the image asset in place rather than redesigning the section around it.
- If an image is clearly temporary, irrelevant, broken or factually misleading, flag it for review rather than silently replacing it with an invented visual.

### Hero preservation rule

Hero sections require special treatment:

- **Keep the existing hero layout as it is.**
- Preserve the current hero's image/video position, text-to-media relationship, CTA placement, spacing and responsive composition.
- Do not introduce a new hero composition, split layout, floating mockup arrangement or full-screen redesign unless that exact change is explicitly approved separately.
- The rebrand should change the typography, colours, copy and visual treatment **within the existing hero layout**, not replace the layout itself.
- Use the existing hero media wherever possible. If a hero currently has a real product image/video, retain it.
- If a hero needs improved media later, swap the asset while keeping the same layout.

### Label-renderer asset rule

Wherever the repository already contains **actual labels generated by the InstaLabel label renderer**, use those labels as the product visuals.

- Prefer renderer-generated InstaLabel labels over random label mockups.
- Reuse the real rendered labels on label pages, homepage galleries, product demonstrations, feature pages and relevant solution pages.
- Show the actual label content at a legible scale.
- Do not invent label text, dimensions, allergens, dates or formatting for marketing visuals.
- If multiple rendered label types already exist, use the relevant real output for Prep, Cooked, Defrost, Ingredient, Expiry and PPDS examples.
- If a page currently shows a renderer-generated label, keep that visual in place during the rebrand.
- New label examples should be generated through the same product/label renderer where possible, rather than designed as independent marketing graphics.

### Staged visual replacement

This rebuild is not a requirement to have the final photography on day one. The implementation should support progressive replacement:

1. **Now:** Preserve existing relevant images and renderer-generated labels.
2. **Next:** Replace temporary/general imagery with approved real product photography as it becomes available.
3. **Later:** Add customer-approved before-and-after photography, printer shots, kitchen environments and case-study images.
4. **Always:** Keep the page section, component and layout stable when an image is replaced.

The goal is to improve authenticity without repeatedly redesigning the site every time a new image becomes available.

### Required shoot list

1. MUNBYN RW411B printing a real InstaLabel label.
2. Born4Ship DB403 printing the same or comparable label.
3. Android tablet paired with the supported printer.
4. Laptop running the web dashboard beside an installed printer using PrintBridge.
5. A staff member selecting a product and label type.
6. A hand applying a prep label to a food container.
7. Close-ups of prep, cook, defrost, ingredient and PPDS labels.
8. A real fridge or prep shelf with labelled containers.
9. Before-and-after image using a genuine handwritten process and genuine output.
10. One owner or chef portrait for each approved customer story.
11. Multi-printer group shot for compatibility messaging.
12. Real dashboard screenshots at native resolution.

### Art direction

- Normal commercial kitchen, stainless steel, believable prep environment.
- Neutral daylight or soft practical lighting.
- No artificial purple lighting.
- Show hands and work naturally, not staged smiles at a camera.
- Keep surfaces clean but not implausibly empty.
- Do not generate fake labels or fake customer environments with AI.
- Capture horizontal, vertical and square crops during the same shoot.

### Screenshot rules

- Use real UI and real feature states.
- Blur or replace private business data deliberately.
- Do not fabricate analytics values.
- Use a simple device frame or border, not a floating 3D collage.
- Add no more than three callouts to a screenshot.

## 9. Messaging system and copy rules

### Messaging hierarchy

1. **What it is:** Kitchen labelling software.
2. **Main difference:** Desktop printing without proprietary hardware.
3. **Core workflow:** Configure once, select, review and print.
4. **Operational value:** Clear, consistent labels and central records.
5. **Compliance support:** Product and allergen data can support the business’s labelling process; the business remains responsible for accuracy and compliance.
6. **Platform truth:** Broad desktop compatibility; model-specific Android compatibility.

### Preferred vocabulary

Use often:

- label, print, product, ingredient, allergen, shelf life;
- configured, approved, recorded, consistent, clear;
- kitchen, staff, location, history, template;
- supported, tested, installed, connected.

Use sparingly:

- AI, intelligent, smart, automated, seamless, powerful, transform.

Avoid unless legally and evidentially approved:

- guaranteed compliance;
- fully compliant;
- 100% compliant;
- EHO approved;
- zero errors;
- no mistakes;
- no training required;
- #1 or best;
- never worry again;
- protects you from fines;
- legal protection;
- any Bluetooth printer;
- automatic allergen detection with no review;
- expiry dates based on universal food-safety rules.

### Approved compliance formulation

> InstaLabel provides tools that support your food-labelling and record-keeping processes. Your business remains responsible for ingredient accuracy, allergen information, shelf-life decisions, staff training and regulatory compliance.

### Approved expiry formulation

> Set the shelf-life rule your business has approved for each product. InstaLabel applies that rule when staff create a label.

### Approved allergen formulation

> Store ingredient and allergen information centrally, review it and use it consistently across labels.

If AI extraction is available:

> Import or extract product information for review. Nothing should become approved product data until an authorised user checks it.

### Approved desktop compatibility formulation

> PrintBridge uses printers installed on your Windows or macOS computer. If the computer can print to the device, PrintBridge can use it.

Engineering must verify the exact operating systems and any exceptions before publication.

### Approved Android compatibility formulation

> Direct Bluetooth printing on Android is available for supported printer models. MUNBYN RW411B and Born4Ship DB403 are currently verified. Rongta support is being tested. More integrations will be added over time.

Do not publish a Rongta brand-wide claim. Add the exact model when known.

**Can I use my existing label printer?**  
On Windows and macOS, PrintBridge can use a printer that is correctly installed and printable through the operating system, subject to label size and driver setup. Android printing requires a supported Bluetooth model.

**Which printers work with Android?**  
MUNBYN RW411B and Born4Ship DB403 are currently verified. Rongta support is being tested for a specific model. Check the compatibility page before purchasing hardware.

**How are expiry dates calculated?**  
Your business sets the shelf-life rule for each product and label type. InstaLabel applies that configured rule from the selected prep, cook or defrost time.

**Does InstaLabel guarantee compliance?**  
No. InstaLabel supports consistent data and labelling workflows, but your business remains responsible for product information, allergens, shelf-life decisions, staff training and legal compliance.

**Can I create PPDS labels?**  
Yes. InstaLabel can use reviewed product and ingredient data to create PPDS label layouts. Your business must confirm whether the product is PPDS and review the final label.

**Is there an iPhone app?**  
The direct-printing mobile app is currently Android only. Use the exact current product status.

**Can I import my menu?**  
State the released CSV workflow. Mention PDF/OCR only when it is available, not while planned.

**Can I try it first?**  
State the current trial length, card requirement and cancellation terms from billing.

**What support is included?**  
State real support hours, channels and onboarding offer.

## 19. Accessibility, performance and responsive requirements

### Accessibility

- Meet WCAG 2.2 AA.
- Verify contrast for every token pairing.
- Visible focus states on all interactive controls.
- Keyboard-accessible navigation, tabs, accordions and menus.
- Minimum 44px touch targets.
- Semantic headings in logical order.
- Descriptive alt text for meaningful images; empty alt for decoration.
- Captions/transcript for explanatory video.
- No information communicated by purple, amber or red alone.
- Respect reduced motion.
- Error summaries and inline field messages for forms.

### Performance

- Target Core Web Vitals in the good range.
- Optimise hero media and use an image poster before video loads.
- Serve responsive AVIF/WebP images with dimensions.
- Avoid autoplay video on constrained connections.
- Self-host and subset fonts where practical.
- Remove unused animation and icon packages.
- Defer analytics and non-essential scripts.
- Do not load the chat widget by default.

### Responsive behaviour

- Test at 360, 390, 768, 1024, 1280 and 1440px widths.
- Compatibility tables need a purposeful mobile layout, not horizontal overflow hidden from users.
- Labels must remain readable on mobile.
- Product screenshots can crop to the focal area with a link to open the full image.
- Sticky mobile CTA is optional, but must not obscure content or cookie controls.
